## O que significa cada pedaço

<Code caption="Antes: função recebe o email, mas o cola dentro da instrução">
```js
function findUser(db, email) {
  return db.query(
    "SELECT usuario_id, nome FROM usuarios WHERE email_usuario = '" + email + "'"
  )
}
```
</Code>

O parâmetro `email` da função JavaScript já existe aqui. Ele guarda o valor recebido. O erro acontece depois: `+ email +` coloca o conteúdo dessa variável dentro da string SQL.

<Code caption="Depois: a mesma função passa o valor separadamente">
```js
function findUser(db, email) {
  return db.query(
    "SELECT usuario_id, nome FROM usuarios WHERE email_usuario = ?",
    [email],
  )
}
```
</Code>

Leia a versão correta em três passos:

1. `findUser(db, email)` recebe o banco e o email como parâmetros da função JavaScript.
2. `WHERE email_cliente = ?` mantém a instrução SQL fixa e cria uma vaga.
3. `[email]` fornece o valor da primeira vaga como segundo argumento de `db.query`.

Um `?` corresponde a um valor. Com duas vagas, a ordem da lista importa:

<Code caption="Duas vagas e dois valores, na mesma ordem">
```js
function listOrders(db, email, status) {
  return db.query(
    "SELECT pedido_id, nome_do_item FROM pedidos WHERE email_cliente = ? AND situacao_do_pedido = ?",
    [email, status],
  )
}
```
</Code>

Aqui, `email` preenche a primeira vaga (`email_cliente`) e `status` preenche a segunda (`situacao_do_pedido`). Eles continuam sendo dados separados da instrução.

Os nomes dizem o papel de cada coluna: `pedido_id` identifica o pedido, `nome_do_item` é o produto e `situacao_do_pedido` guarda valores como `aberto` ou `entregue`.
