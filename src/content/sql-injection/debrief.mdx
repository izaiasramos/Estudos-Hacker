Hora de reconstruir a cena, sem culpar o banco. Em quatro passos:

1. O servidor recebeu um valor de entrada.
2. O código colou esse valor no texto SQL.
3. Com isso, a estrutura da consulta passou a depender da entrada.
4. O analisador do banco leu o texto final, do jeito que chegou.

O banco não sabe qual pedaço "devia" ser só dado. Essa informação se perdeu quando o servidor juntou instrução e entrada num texto único.

<Callout tone="conceito">
O banco não "desobedeceu" ao programa. Ele fez o que o texto recebido mandou. O erro foi do programa, que entregou uma estrutura diferente da que pretendia.
</Callout>

Compare os dois modelos:

- **Concatenação:** primeiro monta um texto variável, depois pede ao banco que descubra a estrutura dele.
- **Parametrização:** primeiro define a estrutura fixa, depois encaixa os valores nas vagas marcadas.

Isso explica o sintoma da lista e já aponta o conserto. Não é preciso decorar nenhuma entrada especial. Basta achar o momento em que um dado passou a fazer parte da instrução.

<Callout tone="dev">
Num relatório de incidente real, registre: de onde veio o valor, qual função montou a consulta, qual estrutura foi enviada e qual foi o impacto. Isso ajuda mais a corrigir e a evitar repetição do que apenas dar nome à vulnerabilidade.
</Callout>

**Em resumo:** o servidor perdeu a separação ao concatenar, o banco leu a consulta final e a correção é separar os papéis antes de enviar.

## Reconstrua também o caminho corrigido

1. A rota recebe `email` do formulário.
2. A rota chama `findUser(db, email)`. Aqui, `email` é o parâmetro da função JavaScript.
3. `findUser` envia a instrução fixa com `?` como primeiro argumento de `db.query`.
4. A função envia `[email]` como segundo argumento.
5. A biblioteca de conexão associa o primeiro valor à primeira vaga e o envia como dado, sem transformar seu conteúdo em instrução.
6. O mesmo payload passa a ser procurado como um email literal e não traz o pedido de Bruno.

<Code caption="A fronteira corrigida em uma única função">
```js
function findUser(db, email) {
  const sql = "SELECT usuario_id, nome FROM usuarios WHERE email_usuario = ?"
  const values = [email]
  return db.query(sql, values)
}
```
</Code>

Dar nomes temporários, como `sql` e `values`, ajuda a enxergar os dois canais. A versão curta `db.query("... = ?", [email])` faz exatamente a mesma separação.
