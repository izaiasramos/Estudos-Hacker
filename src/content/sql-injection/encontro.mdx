Vamos acompanhar o email de Alice dentro do código. Uma **entrada** (*input*) é qualquer valor que vem de fora do programa: um campo de formulário, um pedaço de endereço, um dado de outro sistema. Receber entrada é normal. O perigo está no que o servidor faz com ela.

Aqui está a versão que **cola** o email no texto SQL:

<Code caption="Versão que concatena">
```js
const email = body.email
db.query("SELECT usuario_id FROM usuarios WHERE email_usuario = '" + email + "'")
```
</Code>

Na primeira linha, `email` é só um valor guardado numa variável. Na segunda, o `+` **concatena**, ou seja, junta textos num texto só. Resultado: o email de Alice passa a morar dentro da frase que dá a ordem ao banco.

Agora a versão que **separa**:

<Code caption="Versão que envia o valor à parte">
```js
const email = body.email
db.query("SELECT usuario_id FROM usuarios WHERE email_usuario = ?", [email])
```
</Code>

O `?` é um **placeholder**, um marcador de vaga. O `[email]` entrega o valor pra essa vaga por um canal à parte. Esse jeito se chama **consulta parametrizada**.

## Três peças diferentes chamadas de “parâmetro”

É comum confundir `email`, `?` e `[email]`. Eles se conectam, mas cada um vive em uma parte diferente:

<Code caption="A viagem completa do valor de Alice">
```js
function findUser(db, email) { // 1. email recebe o valor dentro da função JavaScript
  return db.query(
    "SELECT usuario_id FROM usuarios WHERE email_usuario = ?", // 2. ? é uma vaga na instrução SQL
    [email],                                    // 3. o valor da vaga vai separado
  )
}

findUser(db, "alice@exemplo.test") // valor concreto entregue ao parâmetro email
```
</Code>

Sim: a função do servidor tem um parâmetro chamado `email`, esperando receber um valor quando alguém chama `findUser`. Isso já acontecia na versão vulnerável. A proteção não vem apenas de a função “ter um parâmetro”. Ela vem da forma como a função passa esse valor ao banco.

- `email` na assinatura é uma variável da função JavaScript.
- `?` é uma vaga dentro da instrução SQL fixa.
- `[email]` é a lista de valores enviada para preencher as vagas.

Entre o código e o banco existe uma biblioteca de conexão. Ela recebe a instrução SQL e seus valores, envia os dois ao banco da forma correta e devolve o resultado para a aplicação. Essa biblioteca costuma ser chamada de **driver do banco**.

Aqui, `db.query` representa essa biblioteca. Ela não cola `[email]` na frase como se usasse `+`. Em vez disso, envia a instrução e o valor separadamente. Assim, o banco trata o conteúdo de `email` como dado, mesmo quando esse conteúdo parece um comando SQL.

## Do formulário até o banco: onde nasce a falha

O formulário pode ser igual nas duas versões:

<Code caption="1. O navegador envia um campo chamado email">
```html
<form action="/usuarios/buscar" method="post">
  <input name="email" type="email" />
  <button>Buscar</button>
</form>
```
</Code>

A rota também só recebe o campo e chama a função:

<Code caption="2. O servidor lê o email e chama findUser">
```js
export async function POST(request) {
  const form = await request.formData()
  const email = String(form.get("email") ?? "")
  return findUser(db, email)
}
```
</Code>

Receber o email não é a vulnerabilidade. O problema aparece no próximo passo, quando `findUser` decide como conversar com o banco.

<Code caption="3A. Forma errada: o valor ajuda a construir a instrução">
```js
function findUser(db, email) {
  const sql = "SELECT usuario_id, nome FROM usuarios WHERE email_usuario = '" + email + "'"
  return db.query(sql)
}
```
</Code>

<Code caption="3B. Forma correta: instrução fixa e valor separado">
```js
function findUser(db, email) {
  const sql = "SELECT usuario_id, nome FROM usuarios WHERE email_usuario = ?"
  return db.query(sql, [email])
}
```
</Code>

O formulário e a rota não mudaram. Mudou apenas a fronteira na função que consulta o banco.

As duas versões fazem a mesma busca. A diferença é quem controla a frase: na concatenada, o conteúdo do campo ajuda a escrevê-la. Na parametrizada, a frase é fixa e o campo é só preenchimento.
