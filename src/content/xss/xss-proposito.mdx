Uma equipe lança comentários no painel de suporte. Na sexta, alguém cola um texto que parece uma imagem quebrada. Na segunda, cada agente que abre o chamado vê a tela mudar, e uma ação é feita **com a sessão dele**. O comentário devia só ser lido. Em vez disso, deu ordens ao navegador.

**Cross-Site Scripting (XSS)** quer dizer "script entre sites". O nome é histórico, então fique com a ideia: um dado de fora entrou numa página legítima e o navegador o tratou como **HTML ou JavaScript de verdade**. O efeito acontece no navegador de quem abre a página, com a sessão daquela pessoa.

<Callout tone="analogia">
Imagine um mural feito só para exibir bilhetes. XSS é quando o mural lê um bilhete como ordem: "mova esta porta", "envie este formulário". A defesa é garantir que bilhete continue sendo bilhete.
</Callout>

Cookie `HttpOnly` (que o JavaScript não consegue ler) ajuda, mas não encerra o assunto. Um script na página ainda pode mudar a tela, ler o que está visível e disparar ações que o navegador autoriza para aquela sessão.
