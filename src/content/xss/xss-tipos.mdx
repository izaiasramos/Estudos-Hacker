Siga o caminho do comentário. Se ele chega pela busca e volta na mesma resposta, o caso é **XSS refletido**. Se fica salvo em um ticket e atinge visitantes depois, é **XSS armazenado**. Se um script do próprio front-end lê um valor da URL e o escreve de modo inseguro na página, é **XSS baseado no DOM**.

**DOM**, ou *Document Object Model* (Modelo de Objetos do Documento), é a representação em objetos que o navegador constrói para a página. JavaScript consulta e altera essa árvore para criar textos, links e componentes.

O contraste decisivo está na API usada:

<Code caption={"A mesma entrada, duas decisões diferentes"}>

```js
painel.innerHTML = comentario;   // analisa a string como HTML
painel.textContent = comentario; // cria somente um nó de texto
```

</Code>

`innerHTML` é um **sink perigoso** quando recebe dado não confiável: ele pede ao navegador para analisar marcação. `textContent` preserva a intenção de exibir texto. Frameworks como React também escapam valores interpolados como texto por padrão, mas essa proteção pode ser contornada por APIs explícitas de HTML, como `dangerouslySetInnerHTML`.

<Callout tone="conceito">

Refletido, armazenado e baseado no DOM descrevem o trajeto. A falha é a mesma: uma fronteira de confiança foi quebrada e dados passaram a controlar a estrutura ou o comportamento da página.

</Callout>

Ao revisar código, não pare no local em que a entrada chegou. Acompanhe o valor até o ponto de saída e pergunte qual interpretação aquela API solicita ao navegador.
