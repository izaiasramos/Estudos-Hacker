O painel precisa mostrar texto comum e, numa área separada, aceitar formatação rica (negrito, links). Cada necessidade pede uma decisão diferente.

**1. Texto comum.** Use uma função que só cria texto, como `textContent`, ou a interpolação segura do framework. Além disso, **codifique a saída** conforme o lugar: caracteres com significado especial em HTML, atributos ou URLs não podem controlar a estrutura onde forem colocados.

**2. HTML rico (quando é requisito de verdade).** Use um **sanitizador**. Ele lê o HTML e mantém só as tags e atributos de uma lista permitida. Não é a mesma coisa que codificar: codificar mostra as tags como texto, sanitizar mantém as aprovadas funcionando. Bloquear só palavras conhecidas é frágil.

**3. Uma rede de segurança: CSP.** A **Content Security Policy** (Política de Segurança de Conteúdo) diz ao navegador de onde scripts, estilos e outros recursos podem vir. Um **nonce** é um código imprevisível gerado a cada resposta e colocado na política e nos scripts autorizados. Scripts sem o código certo são recusados.

<Callout tone="armadilha">
CSP com nonce é uma camada extra, não um escudo total. Ela dificulta scripts não autorizados, mas não conserta `innerHTML`, não sanitiza nada e perde força se o nonce for reutilizado.
</Callout>

<Callout tone="dev">
Resumo da decisão: texto simples usa DOM seguro. HTML necessário passa por sanitizador. Toda saída respeita o contexto. CSP reduz o estrago se outra barreira falhar.
</Callout>

Um detalhe: não ter CSP não cria XSS sozinho. O risco nasce quando um dado de fora chega num ponto que o interpreta como conteúdo ativo. Cada camada diminui a chance ou o impacto dessa chegada.
