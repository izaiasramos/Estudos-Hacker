Na revisão da rota de avatar, acompanhe três valores: bytes, nome e endereço de entrega. Na versão vulnerável, todos continuam sob controle do cliente.

<Code caption="Upload que confia no cliente">

```
const file = form.get("avatar");
const destino = path.join("public/uploads", file.name);
await fs.writeFile(destino, Buffer.from(await file.arrayBuffer()));
return Response.json({ url: `/uploads/${file.name}` });
```

</Code>

Usar `../../.env` no nome tenta um path traversal: `path.join` monta o caminho, mas não garante que ele permaneça na pasta esperada. O contraste elimina a escolha do cliente:

<Code caption="Upload com decisões do servidor">

```
const file = form.get("avatar");
if (file.size > 2_000_000) return erro("tamanho");

const bytes = Buffer.from(await file.arrayBuffer());
if (!ehPngOuJpeg(bytes)) return erro("tipo");

const png = await reprocessarImagem(bytes);
const id = crypto.randomUUID();
await storage.put(`avatars/${id}.png`, png, { contentType: "image/png" });
return Response.json({ url: `https://arquivos.exemplo.com/avatars/${id}.png` });
```

</Code>

O limite ideal também é aplicado durante a leitura do fluxo, antes de aceitar todos os bytes. O nome original nunca vira caminho. Síntese: o servidor decide o que entra, quanto entra, onde fica e como volta.
