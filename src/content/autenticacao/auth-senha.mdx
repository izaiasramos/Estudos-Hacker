Quando você cria uma conta, o site precisa lembrar da sua senha para conferir depois. A pior ideia é guardá-la do jeito que você digitou. Se o banco de dados vazar, todas as senhas estão ali, prontas para o ladrão testar neste site e em outros (porque muita gente repete a senha).

A solução é guardar **uma versão embaralhada** da senha. Essa versão se chama **hash**.

## O que é hash, sem complicar

Pense num **liquidificador**. Você coloca banana, leite e gelo e sai uma vitamina.

- Se repetir a mesma receita, sai a mesma vitamina.
- Mas ninguém consegue pegar a vitamina e separar de volta a banana, o leite e o gelo.

O hash é um liquidificador para senhas. Você coloca a senha `pizza123`, e sai um código embaralhado, como `9f2c71…b4a0`.

<Diagram name="hash" />

Três coisas importam:

1. **Mesma senha, mesmo código.** Sempre.
2. **Senha diferente, código completamente diferente.** Mesmo que a diferença seja uma letra.
3. **Não dá para voltar.** Do código não se recupera a senha.

### Como o login funciona com isso

O site **nunca guarda a sua senha**. Ele guarda só o código. Quando você tenta entrar:

1. Você digita `pizza123`.
2. O site passa o que você digitou pelo mesmo liquidificador.
3. Compara o código novo com o código guardado.
4. Se forem iguais, a senha estava certa. Se não, o login falha.

Se o banco vazar, o ladrão só leva códigos embaralhados, e não as senhas.

## O problema das senhas iguais, e o sal

Se Ana e Bia usam a mesma senha, `pizza123`, as duas ficam com o **mesmo código**. Quem roubar o banco vê que elas repetem a senha. E pior: existem listas prontas com o código das senhas mais comuns, e o ladrão só precisa comparar.

A correção é o **sal** (*salt*): antes de passar pelo liquidificador, o site mistura **um ingrediente aleatório diferente para cada pessoa**. Cada pessoa ganha o seu sal, e ele pode ficar guardado junto do código, sem problema.

## O liquidificador precisa ser lento

Um computador rápido consegue testar bilhões de palpites por segundo se o hash for rápido. Por isso, para senhas, usamos algoritmos feitos para ser **lentos de propósito**: **bcrypt**, **scrypt** e **Argon2**.

Para você, esperar 0,2 segundo no login não muda nada. Para quem tenta bilhões de palpites, essa lentidão transforma horas em anos.

<Callout tone="armadilha">
Não use hash rápido (como MD5 ou SHA-1 puros) para senhas. Eles servem para outras coisas, mas são rápidos demais e facilitam o chute em massa.
</Callout>

<Code caption="Errado vs. certo">
```
errado: guardar a senha que a pessoa digitou
certo:  guardar algoritmo + custo + sal + hash
```
</Code>

<Callout tone="dev">
Hash não salva uma senha fraca. Se alguém usa `123456`, o ladrão acerta no primeiro palpite, hash ou não. Por isso o cadastro também precisa **recusar senhas curtas, óbvias ou que estejam em listas de senhas comuns**.
</Callout>

**Na prática:** use uma biblioteca atual de bcrypt, scrypt ou Argon2, com sal único por senha, e nunca invente o seu próprio jeito de embaralhar.

## Mão na massa: compare os dois jeitos de guardar senha

Salve como `senha.mjs` e rode `node senha.mjs`. Ele usa o módulo `crypto`, que já vem com o Node. Nada a instalar.

<Code caption="senha.mjs: texto puro vs. salt + hash">
```js
import { randomBytes, scryptSync, timingSafeEqual } from "node:crypto";

// ERRADO: guarda a senha como o usuário digitou
const bancoRuim = { alice: "pizza123" };
console.log("Se o banco vazar:", bancoRuim); // a senha está ali, legível

// CERTO: guarda salt + hash
function criarRegistro(senha) {
  const salt = randomBytes(16).toString("hex");
  const hash = scryptSync(senha, salt, 64).toString("hex");
  return `${salt}:${hash}`;
}
function conferir(senha, registro) {
  const [salt, hash] = registro.split(":");
  const tentativa = scryptSync(senha, salt, 64);
  return timingSafeEqual(tentativa, Buffer.from(hash, "hex"));
}

const registro = criarRegistro("pizza123");
console.log("Se o banco vazar:", registro); // não dá para ler a senha daqui
console.log("Senha certa:", conferir("pizza123", registro));
console.log("Senha errada:", conferir("pizza124", registro));
// Mesma senha, outro salt: registros diferentes
console.log("Iguais?", criarRegistro("pizza123") === criarRegistro("pizza123"));
```
</Code>

**O que observar:**

- No primeiro banco vazado, a senha aparece inteira.
- No segundo, só há `salt:hash`. Quem rouba isso precisa testar palpites um a um, e cada palpite custa tempo (o `scrypt` é lento de propósito).
- A última linha imprime `false`: mesma senha, salts diferentes, registros diferentes.

**Seu desafio:** troque `"pizza123"` por `"123456"` e pense: o hash protege essa senha de quem testa palpites comuns? Não protege. Por isso o cadastro precisa recusar senhas óbvias.
