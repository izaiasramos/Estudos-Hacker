Bloquear a palavra `localhost` parece resolver o caso óbvio, mas não resolve: outro nome pode apontar para o mesmo IP, um IP tem várias formas de escrita e um site público pode redirecionar para dentro.

O **DNS** (sistema de nomes de domínio) traduz um nome como `exemplo.com` em um ou mais IPs. A regra segura segue estes passos:

1. Permita só os protocolos necessários.
2. Resolva o nome e recuse todo IP interno, de loopback ou link-local.
3. Conecte exatamente ao IP que foi validado.

O passo 3 tem uma pegadinha: se a biblioteca resolver o nome de novo na hora de conectar, a resposta do DNS pode ter mudado entre a validação e a conexão. A implementação precisa fixar a conexão no IP conferido, mantendo o nome original para o certificado TLS e para o cabeçalho de host.

**Redirecionamentos** são URLs novas. O ideal é não segui-los. Se seguir, repita todo o processo a cada salto e imponha um limite de saltos. Quando o produto já conhece os destinos possíveis, uma **lista permitida de sites** é mais forte do que tentar listar tudo que é proibido.

<Callout tone="armadilha">
"Eu resolvi e validei" não basta se o cliente HTTP resolver outra vez. Validar um IP e conectar em outro mantém a falha.
</Callout>

Na AWS, o **IMDSv2** exige um token temporário para consultar os dados da máquina, o que dificulta ataques simples. Mas ele não substitui bloquear o endereço `169.254.169.254` nem restringir a saída de rede.

<Glossary term="Serviço de metadados" text={"Um endereço especial dentro dos servidores na nuvem que informa dados da própria máquina e, às vezes, senhas temporárias. Só deveria ser acessível de dentro."} example={"O endereço 169.254.169.254, famoso em ataques SSRF."} />

**Em resumo:** valide o destino real, conecte no que validou e trate cada redirecionamento como uma nova decisão.

## Mão na massa: valide o destino antes de buscar

Salve como `validar-url.mjs` e rode `node validar-url.mjs`. A função confere o protocolo e resolve o nome para IP antes de decidir.

<Code caption="validar-url.mjs: só HTTPS e só IP público">
```js
import { lookup } from "node:dns/promises";
import { isIP } from "node:net";

function ipInterno(ip) {
  return /^(127\.|10\.|192\.168\.|169\.254\.|172\.(1[6-9]|2\d|3[01])\.|0\.)/.test(ip) || ip === "::1";
}

export async function urlPermitida(texto) {
  const url = new URL(texto);
  if (url.protocol !== "https:") return false;
  const ips = isIP(url.hostname) ? [url.hostname] : (await lookup(url.hostname, { all: true })).map((r) => r.address);
  return ips.every((ip) => !ipInterno(ip));
}

console.log(await urlPermitida("https://example.com"));   // true
console.log(await urlPermitida("http://127.0.0.1:9000")); // false (HTTP e IP interno)
console.log(await urlPermitida("https://127.1/"));        // false: o Node entende 127.1 como 127.0.0.1
```
</Code>

**O que observar:** o `127.1` é um jeito curto de escrever `127.0.0.1`, e o Node o converte. Barrar a palavra `localhost` não pegaria isso. Conferir o **IP resolvido** pega.

**Seu desafio:** ligue essa função à prévia do `ssrf.mjs`: chame `urlPermitida(alvo)` antes do `fetch` e devolva erro se der `false`. Depois repita o teste com `http://127.0.0.1:9000`.

<Callout tone="armadilha">
Este exemplo mostra a validação, mas ainda tem a brecha do DNS: o `fetch` resolve o nome outra vez na hora de conectar. Em produção, conecte ao IP validado ou isole a busca numa rede sem acesso interno.
</Callout>
