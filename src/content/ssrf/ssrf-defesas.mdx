Bloquear a palavra `localhost` parece resolver o caso óbvio. Não resolve: outro nome pode chegar ao mesmo IP, um IP pode ter representações diferentes e um destino público pode redirecionar para dentro.

Domain Name System (DNS), sistema de nomes de domínio, traduz um nome como `exemplo.com` em um ou mais IPs. A regra segura permite apenas os esquemas necessários, resolve o nome, recusa todos os candidatos internos, loopback ou link-local e conecta exatamente ao destino validado. Se a biblioteca resolver o nome outra vez durante a conexão, surge uma janela em que a resposta DNS pode mudar. A implementação precisa fixar a conexão ao IP conferido, preservando o nome original para validação do certificado TLS e para o cabeçalho de host.

Cada redirecionamento é uma URL nova: prefira não seguir; se seguir, repita todo o processo e imponha um limite de saltos. Quando o produto conhece os destinos, uma lista permitida de hosts é mais forte que tentar listar tudo o que é proibido.

<Callout tone="armadilha">

“Resolvi e validei” não basta se o cliente HTTP resolver novamente. Validar um IP e conectar por outro mantém a falha.

</Callout>

Amazon Web Services (AWS) oferece o Instance Metadata Service version 2 (IMDSv2), serviço de metadados de instância versão 2. Ele exige um token temporário para consultar dados da máquina e reduz ataques simples, mas não substitui bloquear o endereço link-local `169.254.169.254` nem restringir a saída de rede.

<Glossary term="Serviço de metadados" text="Endpoint interno usado por plataformas de nuvem para fornecer dados da máquina e, em alguns casos, credenciais temporárias. Não deve ser alcançável por uma busca controlada pelo usuário." />

Síntese: valide o destino real, conecte ao que validou e trate cada salto como uma nova decisão.
