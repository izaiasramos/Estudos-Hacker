Na aba Network, painel do navegador que mostra pedidos e respostas, compare o que a tela precisa com o que realmente chegou. A primeira resposta expõe campos e usa uma política de script fraca.

<Code caption="Resposta que fala demais">

```
HTTP/1.1 200 OK
X-Powered-By: Express 4.17.1
Content-Security-Policy: script-src 'self' 'unsafe-inline'

{ "id": 7, "name": "Alice", "password_hash": "$2b$12$…", "reset_token": "9f2c…" }
```

</Code>

<Code caption="Resposta reduzida e orientada">

```
HTTP/1.1 200 OK
Content-Security-Policy: script-src 'self' 'nonce-…' 'strict-dynamic'; frame-ancestors 'self'
Strict-Transport-Security: max-age=63072000; includeSubDomains
X-Content-Type-Options: nosniff

{ "id": 7, "name": "Alice", "email": "alice@lab.local" }
```

</Code>

A decisão não é “limpar no navegador”. A rota seleciona uma lista permitida de campos antes de serializar o JSON, troca a pilha por erro público genérico e adiciona as políticas adequadas à resposta.

Síntese: se chegou ao cliente, já foi exposto.
